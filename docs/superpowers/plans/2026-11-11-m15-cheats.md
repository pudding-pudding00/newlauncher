# M15 Cheats und Patches Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Gecko-Codes laden, auswählen und beim Start anwenden: Wii über einen Codehandler aus belegter GPL-Quelle, GC über Nintendont.
- WIP-Patches für Wii-Spiele.

**Architecture:**
- Plattformfrei und host-getestet:
  - `core/gecko_txt` (Parser);
  - `core/gct` (Bauer);
  - `core/cheat_select` (`.sel`-Datei);
  - `core/wip_patch` (WIP-Parser).
- Der Download läuft als Auftrag über den `NetService` (M11).
- Wii:
  - der Codehandler wird aus Quelltext gebaut (`boot/nl/codehandler/`, `NL_BOOTER_CHEATS=1`);
  - die GCT liegt in einem reservierten MEM2-Bereich, auf den `the_CFG.cheats` zeigt.
- GC: `NIN_CFG` bekommt `CHEATS|CHEAT_PATH` und den Pfad zu einer GCT auf dem Spielgerät.

**Tech Stack:** C++20, PowerPC-Assembler (devkitPPC `powerpc-eabi-as`), doctest, Dolphin.

**Spec:** `docs/superpowers/specs/2026-11-11-v2-universell-design.md` – 3.2, 3.3, 4.5, 8, 15.

**Basis-Branch:** `feat/m15-cheats` von `main` nach M14.

## Global Constraints

- **Kein Code-Blob ohne Quelle.** Der Codehandler wird im Build aus `.s`-Quelltext assembliert. Seine Lizenz ist GPLv3-verträglich und in `THIRD_PARTY.md` belegt. `check_licenses.py` bleibt grün.
- **Kein automatischer Download.** Codes kommen nur auf Knopfdruck. Eigene Dateien in `<data>/codes/` werden nie überschrieben: Ein Download in eine vorhandene Datei fragt nach.
- **Codes mit Platzhaltern** (`X`/`x` in einer Codezeile) werden angezeigt, sind aber nicht wählbar.
- **Größengrenze der GCT:**
  - Wii: `codelistend − codelist` des gebauten Codehandlers;
  - GC: Grenze aus Nintendont (Step in Task 6).
  - Eine Überschreitung ist ein Preflight-Fehler mit Größe in Bytes.
- **`hook`:** `vbi|kpad|joypad|gxdraw|gxflush|ossleep|axframe` → 1–7, Standard `vbi`. Ohne Cheats wird kein Hook gesetzt (`hooktype = 0`).
- **Fällt der Codehandler-Spike negativ aus:** Wii-Cheats bleiben aus (`NL_BOOTER_CHEATS=0`). Die Cheat-Szene zeigt bei Wii-Spielen „Wii-Cheats in dieser Version nicht verfügbar“. GC-Cheats und WIP laufen trotzdem.
- **Texte** DE/EN; Wii-Build warnungsfrei ON/OFF; alle früheren Smokes grün.

## Review Focus

1. Gecko-Datei mit CRLF, UTF-8-BOM, Tabs statt Leerzeichen, 1-MB-Kommentarblock, Code ohne Namen oder mit ungerader Zeilenhälfte: Der Parser bricht nicht ab. Kaputte Blöcke werden übersprungen und gezählt (`NL_CHEAT_SKIP <n>`).
2. `.sel` nennt einen Code, den es nach einem Neuladen nicht mehr gibt: Er wird stillschweigend entfernt. Ein Name, der doppelt in der Datei steht, wird nur einmal angewendet.
3. Download liefert eine HTML-Fehlerseite mit Status 200 oder eine leere Datei: Nach dem Parsen hat sie keine ID6 in Zeile 1 → „Keine Codes für dieses Spiel gefunden“. Die Datei wird nicht gespeichert.
4. WIP-Zeile mit Offset außerhalb des Hauptspeichers oder ungeradem Hex: Sie wird übersprungen und geloggt. Höchstens 1024 Einträge.
5. GC-Spiel auf `usb2`: Die GCT liegt auf `usb2`, `CheatPath` verweist auf dieses Gerät im Nintendont-Format. Nintendont findet sie (Hardware-W-Punkt).
