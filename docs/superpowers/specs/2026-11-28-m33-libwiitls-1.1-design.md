# M33: `libwiitls v1.1.0` Upgrade & Feature Adoption Design

Status: Draft Spec (2026-11-28) · Tracks: [Issue #5](https://github.com/pudding-pudding00/newlauncher/issues/5)

## 1. Purpose & Goals

Upgrade the vendored TLS/HTTP library (`third_party/wii_tls`) from **libwiitls v1.0.0** to **libwiitls v1.1.0** (`pudding-pudding00/libwiitls`) once tagged, capturing:

1. **Critical upstream performance & security fixes** (~10x faster sequential HTTP/2 on Wii via frame coalescing, HPACK heap use-after-free fix, HTTP/2 trailer decoding fix, non-blocking write duplicate-record fix, bundled zlib 1.4).
2. **Safe handling of the v1.1.0 Dolphin entropy security change** (`WTLS_DOLPHIN_DEV_ENTROPY`) without ever weakening production/release Wii builds.
3. **Selective adoption of v1.1.0 features that concretely benefit newlauncher**, while explicitly disabling non-beneficial features to protect binary size, RAM, and security surface.

All `AGENTS.md` TLS hard rules remain strictly binding:
- Every `wtls_*` call runs **only on the `NetService` thread**.
- **Never** fall back from HTTPS to HTTP.
- **Never** disable certificate verification.
- **Never** commit private keys or enable `WTLS_KEYLOG` in release builds.
- Update `third_party/wii_tls` **only** via `python tools/vendor_wii_tls.py <checkout> --rev v1.1.0`.

## 2. Vendoring & CMake Configuration

### 2.1 CMake Options (`CMakeLists.txt`)

Keep proven v1.0.0 performance/security flags and explicitly configure new v1.1.0 options:

```cmake
set(WTLS_PLATFORM ogc CACHE STRING "" FORCE)
set(WTLS_EVEREST ON CACHE BOOL "" FORCE)
set(WTLS_ACCEL ON CACHE BOOL "" FORCE)
set(WTLS_ACCEL_P256 ON CACHE BOOL "" FORCE)
set(WTLS_OPT O3 CACHE STRING "" FORCE)
set(WTLS_GZIP ON CACHE BOOL "" FORCE)
set(WTLS_HTTP2 ON CACHE BOOL "" FORCE)
set(WTLS_EMBED_CA ON CACHE BOOL "" FORCE)
# Explicit v1.1.0 disables (unused or debug-only):
set(WTLS_WEBSOCKET OFF CACHE BOOL "" FORCE)
set(WTLS_BROTLI OFF CACHE BOOL "" FORCE)
set(WTLS_ZSTD OFF CACHE BOOL "" FORCE)
set(WTLS_KEYLOG OFF CACHE BOOL "" FORCE)
set(WTLS_BUILD_TESTS OFF CACHE BOOL "" FORCE)
set(WTLS_BUILD_HWTEST OFF CACHE BOOL "" FORCE)
set(WTLS_BUILD_BENCH OFF CACHE BOOL "" FORCE)
set(WTLS_BUILD_EXAMPLES OFF CACHE BOOL "" FORCE)
set(WTLS_BUILD_CURL_SHIM OFF CACHE BOOL "" FORCE)
set(WTLS_BUILD_FUZZ OFF CACHE BOOL "" FORCE)
set(WTLS_INSTALL OFF CACHE BOOL "" FORCE)
```

- Check `wtls_zlib` symbol collision (`z_errmsg=wtls_z_errmsg`) against bundled zlib 1.4: remove the workaround if zlib 1.4 resolves it cleanly, otherwise keep the scoped target definition and document it.

### 2.2 Dolphin Entropy Guard & Dev-Only Build Separation (Mandatory Breaking Change)

In `libwiitls v1.1.0`, `wtls_init()` and `wtls_init_step()` fail closed with `WTLS_ERR_ENTROPY` when `/dev/dolphin` is detected because Dolphin's IOS IPC timing jitter has ~0 bits of min-entropy.

- **Production/Release Build (`build/wii/newlauncher.dol`):**
  - `option(NL_DOLPHIN_DEV_TLS "DEV ONLY: allow predictable entropy in Dolphin" OFF)` — defaults to **`OFF`**.
  - Sets `WTLS_DOLPHIN_DEV_ENTROPY` strictly from `NL_DOLPHIN_DEV_TLS` (`FORCE`).
  - Release builds MUST ALWAYS have `NL_DOLPHIN_DEV_TLS=OFF` and `WTLS_KEYLOG=OFF`.
- **Dev-Only Dolphin TLS Smoke Build (`build/wii-dolphin/newlauncher.dol`):**
  - Add `--dolphin-dev-tls` flag to `tools/build_wii.py` (and helper in `tools/devkitpro.py`), configuring a separate directory `build/wii-dolphin/` with `-DNL_TLS=ON -DNL_DOLPHIN_DEV_TLS=ON`.
  - Print a loud warning during build (`DEV BUILD ONLY — DO NOT DISTRIBUTE`).
  - `tools/dolphin_smoke.py` uses `build/wii-dolphin/newlauncher.dol` for TLS/HTTPS smokes (covers, cheats, cloud fake, self-update), while keeping a dedicated negative smoke asserting that production `build/wii/newlauncher.dol` refuses TLS in Dolphin (`WTLS_ERR_ENTROPY` / `NL_TLS_INIT fail`).
- **Release Gate (`tools/make_release.py` + `.github/workflows/release.yml`):**
  - `tools/make_release.py` refuses to package any DOL from `build/wii-dolphin/` or any build directory whose `CMakeCache.txt` contains `WTLS_DOLPHIN_DEV_ENTROPY:BOOL=ON` or `WTLS_KEYLOG:BOOL=ON`.

## 3. Adopted `libwiitls v1.1.0` Features

### 3.1 Interruptible & Bounded DNS (`wtls_options::dns_timeout_ms`)

- Set `tlsOpt.dns_timeout_ms = kTlsDnsMs` (`8000` ms) on all `wtls_options` in `src/platform/http_client.cpp`.
- In `libwiitls v1.1.0`, `wtls_connect()` runs DNS on the async resolver thread on Wii and honors both `abort_cb` and `dns_timeout_ms`.
- Removes the last uninterruptible blocking call during cover downloads, cloud sync cancellation, and launcher shutdown.

### 3.2 Non-Blocking Startup Entropy Warm-Up (`wtls_init_start()` / `wtls_init_step()`)

- Currently `NetService::prepare()` blocks on `wtls_init()` on the first HTTPS job.
- Update `NetService::loop()` (`src/platform/net_service.cpp`):
  - When `NL_TLS` is enabled and TLS is not yet initialized, call `wtls_init_start()` when the `NetService` thread begins (this needs no network yet!) and step `wtls_init_step(15)` in 15 ms slices during idle/startup cycles (waking promptly if `stop_` or a high-priority job arrives).
  - Once `netUp_` is true, the finishing `wtls_init_step()` completes `psa_crypto_init()` and sets `tlsUp_ = true`, logging `NL_TLS_INIT ok|fail code=<n>`.
  - If a job arrives before warm-up finishes, `prepare()` drives remaining `wtls_init_step(15)` slices (checking `stop_` / job cancel) until `WTLS_OK` or error.
  - All `wtls_*` calls stay strictly inside `NetService::loop()` (single thread).

### 3.3 Persistent SNTP Clock Correction (`wtls_time_save()` / `wtls_time_load()`)

- Store clock correction at `<data>/cache/sntp_offset.bin` (path helper in `src/core/data_dir.{hpp,cpp}`: `sntpOffsetPath(dataRoot)`).
- Max age constant: `kSntpCacheMaxAgeSec = 7u * 24u * 3600u` (7 days).
- On `NetService` startup (before first TLS request): call `wtls_time_load(path, kSntpCacheMaxAgeSec)`. If `WTLS_OK`, log `NL_TLS_TIMESYNC cached`.
- After every successful `wtls_time_sync_sntp()`: ensure `<data>/cache` exists and call `wtls_time_save(path)` (non-fatal on write failure).
- Retain existing `WTLS_ERR_CERT` (`BADCERT_EXPIRED`/`FUTURE`) fresh-SNTP fallback if a cached offset ever becomes stale.

### 3.4 Resumable, Crash-Safe, Verified Downloads (`wtls_http_download()` / `wtls_http_download_recover()`)

- Upgrade `platform::httpDownload()` (`src/platform/http_client.{hpp,cpp}`) to use `wtls_http_download()` under `NL_TLS`:
  - Supports optional expected `std::optional<std::array<u8, 32>> expectedSha256` parameter.
  - Uses `<destFile>.part` + `<destFile>.part.meta` for `Range`/`If-Range` resume after Wi-Fi drops, `sync_every_bytes = 262144` (256 KiB), `max_size = maxBody`, and `progress_cb` updating `*received` (including resumed bytes).
  - Calls `wtls_http_download_recover(destFile)` automatically before starting so a power loss during final rename self-heals on FAT32.
  - On `WTLS_ERR_INTEGRITY`, `libwiitls` automatically deletes corrupt `.part` files and leaves `destFile` untouched; map to `NetError::Integrity`.
- **Self-Update Integrity (`src/core/self_update.{hpp,cpp}` + `tools/make_release.py`):**
  - Extend `update.ini` with optional `sha256 = <64 lowercase hex chars>`.
  - `tools/make_release.py` writes `sha256` automatically when generating `update.ini`.
  - `parseUpdateManifest()` validates `sha256` if present (rejects malformed hex, remains backwards-compatible if omitted on older manifests) and passes it to `httpDownload()`.

### 3.5 Request Deadlines & Retry Policy (`src/core/http_policy.{hpp,cpp}`)

Create a pure, host-testable policy table in `src/core/http_policy.{hpp,cpp}` mapped onto `wtls_http_request` fields (`total_timeout_ms`, `max_retries`, `retry_backoff_ms`, `retry_on_503`):

| Profile (`HttpProfile`) | Used For | `total_timeout_ms` | `max_retries` | `retry_backoff_ms` | `retry_on_503` |
|---|---|---|---|---|---|
| `Asset` | Cover images, cheats, OSC catalog, `update.ini` | `25000` | `2` | `500` | `true` |
| `CloudRead` | Idempotent cloud GET/HEAD (list, stat, download) | `30000` | `2` | `1000` | `true` (honors `429`/`503` `Retry-After`) |
| `CloudMutate` | Cloud POST/PUT/PATCH/DELETE (OAuth, uploads, revoke) | `60000` | `0` | `0` | `false` (mutations remain governed by outbox/conflict flow) |
| `LargeDownload` | Emulator ZIPs, Self-Update ZIP (`wtls_http_download`) | `0` (per-stage I/O + resume) | `2` | `1000` | `true` |

### 3.6 Structured Diagnostic Logging (`wtls_set_log_cb()`)

- Register `wtls_set_log_cb` on the `NetService` thread before `wtls_init_start()`:
  - Default level: `WTLS_LOG_WARN` (`WTLS_LOG_CAT_ALL`).
  - When `[debug] perf = 1`: `WTLS_LOG_INFO` (`WTLS_LOG_CAT_ALL`).
  - Format: `NL_WTLS <err|warn|info> <msg>` routed through the thread-safe log sink.
  - Privacy guarantee: `libwiitls` never logs request/response bodies, header values, or key material.

### 3.7 Optional Runtime CA Bundle Refresh (`wtls_load_ca_bundle_file()`)

- Keep `WTLS_EMBED_CA=ON` so the launcher works out of the box with zero SD setup.
- If a user places `<data>/cacert.pem` on SD/USB (for future root CA rotations without rebuilding):
  - On first TLS job (alongside `loadTestCa`), call `wtls_load_ca_bundle_file(path, /*replace_builtin=*/false, &nLoaded)`.
  - Log `NL_TLS_CA_BUNDLE ok n=<nLoaded>` or `NL_TLS_CA_BUNDLE fail`; failure leaves the embedded Mozilla CA bundle intact.
  - Never disables or weakens certificate verification.

### 3.8 Status Code & Error Text Updates (`src/core/net_error.{hpp,cpp}`)

- Add `NetError::Integrity` and `NetError::Entropy` (or map `WTLS_ERR_INTEGRITY` → `Integrity`, `WTLS_ERR_ENTROPY` → `TlsMissing`/`Entropy`, `WTLS_ERR_FILE` → `Other`, `WTLS_ERR_UNSUPPORTED` → `Other`).
- Add `wtls_status` constants in `src/core/net_error.hpp` and verify with `static_assert` in `src/platform/net_service.cpp`:
  - `kUnsupported = -14`, `kEntropy = -20`, `kFile = -60`, `kIntegrity = -61`.
- Add clear DE + EN error descriptions in `src/ui/strings.hpp` for `Integrity` (checksum mismatch) and `Entropy` (random generator unavailable).

## 4. Explicitly Skipped `libwiitls v1.1.0` Features

| Feature | Decision | Rationale |
|---|---|---|
| HTTP/2 Multiplexing (`wtls_http_start` / `wtls_http_wait`) | **Skip** | `libwiitls 1.1.0` Wii benchmarks prove multiplexing does not beat sequential HTTP/2 on Wii due to per-response IOS IPC; sequential HTTP/2 frame coalescing already delivers the ~10x speedup (~62 ms → ~9 ms/req). |
| WebSockets (`WTLS_WEBSOCKET=OFF`) | **Skip** | Unused by launcher; disabling saves code size. |
| Brotli / Zstd (`WTLS_BROTLI=OFF`, `WTLS_ZSTD=OFF`) | **Skip** | Covers (PNG) and saves/emulators (ZIP) are already compressed; JSON/INI endpoints use gzip/deflate; disabling saves RAM and flash. |
| TLS Keylog (`WTLS_KEYLOG=OFF`) | **Skip** | Debug-only secret exporter; must stay `OFF` in release builds. |
| Cookie Jar / Proxies / SOCKS5 | **Skip** | Not required by OAuth/REST/CDN/GitHub flows. |
| Custom Allocator (`wtls_set_allocator`) | **Defer** | libogc default allocator already uses MEM2; only revisit if hardware perf measurements show MEM1 pressure. |

## 6. Verification Strategy (No-Wii-First)

1. **`[HOST]`:**
   - `tests/host/core/http_policy_test.cpp` (profile timeouts/retries/idempotency rules).
   - `tests/host/core/net_error_test.cpp` (new v1.1.0 status codes & names).
   - `tests/host/core/self_update_test.cpp` (optional `sha256` manifest parsing, valid/invalid/missing).
   - `tests/host/core/data_dir_test.cpp` (`sntpOffsetPath`, optional `cacert.pem` path).
   - `tools/tests/test_make_release.py` (`sha256` emitted in `update.ini`, release gate rejecting `WTLS_DOLPHIN_DEV_ENTROPY=ON` or `WTLS_KEYLOG=ON`).
   - `tools/tests/test_devkitpro.py` (`--dolphin-dev-tls` build invocation & separate `build/wii-dolphin/` directory).
2. **`[BUILD]`:**
   - `python tools/build_wii.py` (production TLS, `WTLS_DOLPHIN_DEV_ENTROPY=OFF`, 0 warnings)
   - `python tools/build_wii.py --no-tls` (no TLS, 0 warnings)
   - `python tools/build_wii.py --dolphin-dev-tls` (dev Dolphin TLS, 0 warnings)
   - `python tools/check_licenses.py build/wii`
3. **`[DOLPHIN]`:**
   - Negative smoke: production `build/wii/newlauncher.dol` fails closed with `WTLS_ERR_ENTROPY` in Dolphin (`NL_TLS_INIT fail`).
   - Positive TLS smokes using `build/wii-dolphin/newlauncher.dol`: existing covers, cheats, emulators, self-update (including SHA-256 verification & mismatch rejection + resume from partial `.part` file), and all 3 cloud fakes (`drive`, `onedrive`, `dropbox`) + persistent `sntp_offset.bin` smoke.
4. **`[WII-HW]` (Final Hardware Phase Only):** `docs/acceptance/m33-wii.md` — real Wii verification of production `build/wii/newlauncher.dol` (real IOS jitter entropy passes `wtls_init_step()`, HTTP/2 cover batch latency improvement measured with `[debug] perf=1`, DNS cancel responsiveness, SNTP cache hit on second boot, interrupted download resume, and cloud sync).
