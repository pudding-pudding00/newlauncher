# M17 Eingabe und Komfort Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Classic Controller, Themes, Genres und eigene Kategorien, Spielstatistik und Kindersicherung.

**Architecture:**
- Eingabe: `platform/wii_input` liest den Classic Controller in eigene `RawInput`-Bits. `ui::InputMapper` bildet sie nach Spec 10.1 auf Aktionen ab. UI-Code kennt weiter nur Aktionen.
- Themes, Kategorien, Statistik und Kindersicherung haben je ein host-getestetes Modell in `core/`. `ui/` zeichnet nur.
- Alle neuen Dateien liegen unter `<data>` (M12 Task 3). Sie werden über `.tmp` + Umbenennen geschrieben, auf nicht beschreibbaren Geräten gar nicht.

**Tech Stack:** C++20, devkitPPC/libogc (WPAD Classic), doctest, Python (`prepare_meta.py`).

**Spec:** `docs/superpowers/specs/2026-11-11-v2-universell-design.md` – 10.1–10.5, 13; Basis-Spec 3.6 (Tokens), 3.8 (Eingabe), 5.5/6.3 (`meta.bin`).

**Basis-Branch:** `feat/m17-komfort` von `main` nach M14. Inhaltlich hängt M17 nur von M12 ab (Spec 14); die Classic-Taste `+` braucht aber `Action::Options` und die Options-Szene aus M14.

## Global Constraints

- **Classic-Belegung genau nach Spec 10.1:**

  | Aktion | Classic |
  |---|---|
  | Navigieren | Steuerkreuz, linker Stick |
  | Bestätigen / Zurück | A / B |
  | Konsole wechseln | L / R |
  | Favorit | Y |
  | Suche | X |
  | Optionen | + |
  | HOME-Menü | HOME |
  | Debug-Overlay | ZL + ZR |

  Classic `−`, rechter Stick und `ZL`/`ZR` einzeln sind unbelegt. Alle Controller bleiben verodert.
- **Theme-Tokens:** genau die 14 Felder von `Theme` (`core/theme.hpp`). In `theme.ini` heißen sie `bg, bar, bar_border, tile, tile_focus, text, text2, text_muted, accent, on_accent, accent_soft, accent_soft_text, overlay_dim, danger`. Werte `#RRGGBB` oder `#RRGGBBAA`.
- **Kaputte oder fehlende Werte** nehmen das Standard-Token; der Log schreibt `NL_THEME_BAD <token>`. Ein kaputtes Theme verhindert nie den Start.
- **`meta.bin` v2 bleibt rückwärts lesbar:**
  - Der Launcher liest v1 und v2.
  - `prepare_meta.py` schreibt v2.
  - v1 bedeutet: keine Genres und keine Bewertungen.
- **Kindersicherung:**
  - PIN mit 4 Ziffern, gespeichert als `SHA-256(salt ‖ pin)` mit 16 Byte Salz. Das Salz liefert `randomBytes(16)` in `platform/system`: SHA-256 über 64 `gettime()`-Werte aus einer Warteschleife. Ein Kinderschloss, kein Tresor; das Salz muss nur je Konsole verschieden sein.
  - Ohne gesetzte PIN ist die Kindersicherung aus. Die PIN wird nie geloggt.
  - Ein Start eines gesperrten Spiels, die Einstellungen der Kindersicherung und „Einrichtung“ verlangen die PIN.
- Texte DE/EN; Wii-Build warnungsfrei ON/OFF; alle früheren Smokes grün; eine v1-`config.ini` startet unverändert.

## Review Focus

1. Classic Controller wird während des Betriebs ab- und angesteckt oder gegen einen Nunchuk getauscht: kein hängender Knopf (gehaltene Bits verschwinden mit der Erweiterung), keine Doppelauslösung beim Wechsel.
2. `theme.ini` mit Groß-/Kleinschreibung (`#ffFFff`), ohne `#`, mit Leerzeichen, mit drei- oder fünfstelligen Werten, mit `[dark]` ohne `[light]`: Nur gültige Werte greifen, je kaputtem Token eine `NL_THEME_BAD`-Zeile.
3. `background.png` größer als 640×480, mit Palette, mit Alpha oder kaputt: größer oder kaputt → abgelehnt mit `NL_THEME_BAD background`, sonst angezeigt; nie ein Absturz und nie mehr als 1,2 MiB Textur.
4. `stats.ini` mit 5000 Einträgen, kaputten Zeilen oder Zeit in der Zukunft: Laden < 100 ms auf dem Host-Benchmark, kaputte Zeilen ignoriert, Sortierung stabil.
5. Kindersicherung: falsche PIN dreimal → 30 s Sperre der Eingabe (nicht der Konsole); Spiel ohne Bewertung bei „unbewertet sperren“ gesperrt; HOME-Menü und „Zurück zum Wii-Menü“ bleiben ohne PIN erreichbar.

**Files:**
- Create: `src/core/sha256.hpp/.cpp`, `tests/host/core/sha256_test.cpp`, `src/core/parental.hpp/.cpp`, `tests/host/core/parental_test.cpp`, `src/ui/pin_scene.hpp/.cpp`, `docs/superpowers/spikes/m17-sysconf-pc.md`

**Interfaces:**
- Produces:
  ```cpp
  std::array<u8, 32> sha256(std::span<const u8> data);   // eigene Umsetzung nach FIPS 180-4
  struct ParentalConfig { std::array<u8,32> pinHash{}; std::array<u8,16> salt{}; bool enabled = false;
                          RatingSystem system = RatingSystem::Pegi; u8 maxAge = 18; bool lockUnrated = false; };
  ParentalConfig parentalFromIni(const IniDoc& ini);
  bool checkPin(const ParentalConfig& c, std::string_view pin);              // genau 4 Ziffern
  ParentalConfig withPin(ParentalConfig c, std::string_view pin, std::span<const u8, 16> salt);
  bool isLocked(const ParentalConfig& c, const Rating& r, bool lockedFlag);  // lockedFlag aus [game <schlüssel>] locked = 1
  class PinGate { public: bool submit(bool ok, u32 nowMs); bool blocked(u32 nowMs) const; };  // 3 Fehler → 30 s
  ```
  - Ein Spiel ist gesperrt, wenn `lockedFlag` gilt, oder wenn es im gewählten System bewertet ist und `age > maxAge`, oder wenn es unbewertet ist und `lockUnrated` gilt. Bewertung in einem anderen System zählt als unbewertet.
- Spike „Wii-Jugendschutz übernehmen“ (Spec 10.5): Format von `IPL.PC` in `SYSCONF` aus öffentlichen Quellen (Dolphin-Quelltext `SysConf`, WiiBrew) bestimmen. Positiv → Option `use_wii` liest Stufe und PIN; negativ → Option entfällt, Ruling im Ledger.

- [ ] **Step 1: Spike** `IPL.PC` ins Spike-Dokument (Layout, Felder für Stufe, Bewertungssystem, PIN).
- [ ] **Step 2: Failing tests:**
  - `sha256`: FIPS-Vektoren `""`, `"abc"`, 448-Bit-Nachricht, 1 Mio × `a`;
  - `withPin` + `checkPin` richtig/falsch; `"12a4"` und `"12345"` → false;
  - `isLocked`: PEGI 16 bei `maxAge = 12` → gesperrt; USK-bewertet bei System PEGI → unbewertet;
  - `lockUnrated` + unbewertet → gesperrt;
  - `PinGate`: drei Fehler → `blocked` 30 s, danach frei;
  - bei positivem Spike: `SYSCONF`-Fixture → Stufe und PIN.
- [ ] **Step 3:** FAIL. **Step 4:** implementieren; das Salz kommt aus `platform/system` (`randomBytes(16)`), im Host-Test fest.
- [ ] **Step 5:** Host-Suite grün; Wii-Build 0 Warnungen.
- [ ] **Step 6: Smoke.** `[parental]` mit Fixture-Hash (PIN `1234`), `max_age = 12`, Fixture-Spiel PEGI 16, `[debug] pin_input = 0000` → `NL_PARENTAL denied`; mit `1234` → `NL_PARENTAL ok` und Dry-Run-Start.
- [ ] **Step 7: Commit** `feat: Kindersicherung`
