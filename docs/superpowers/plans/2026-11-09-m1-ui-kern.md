# M1 – Renderer und UI-Kern: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Der Launcher zeigt in Dolphin den Hauptbildschirm (Layout A mit Infoleiste unten) mit Testdaten, bedienbar mit Wiimote-Zeiger, Steuerkreuz, Nunchuk und GameCube-Pad, inklusive Hell/Dunkel-Thema, HOME-Menü, Debug-Overlay und Absturzbildschirm.

**Architecture:** Alles Plattformfreie (Theme, Layout, Eingabe-Mapping, Szenen, Textmessung, Draw-Liste) liegt in der statischen Bibliothek `nl_core` und wird auf dem Host mit doctest getestet. Die UI schreibt pro Frame Quads in eine `DrawList` fester Kapazität; nur `gfx::Renderer` (GX), `gfx::font_loader` (FreeType), `platform::WiiInput` (WPAD/PAD) und `platform::crash` kennen die Wii. Ein einziger I8-Atlas (1024×512) enthält weißen Block, Kreis und alle Glyphen, damit die gesamte UI ein Draw-Call ist.

**Tech Stack:** C++20 ohne Exceptions/RTTI, devkitPPC r51, libogc 3.2.1, FreeType 2.14 (`ppc-freetype`), CMake-Presets `host` und `wii`, doctest 2.4.11, Python-stdlib-Tools, Dolphin 2609b.

**Spec:** `docs/superpowers/specs/2026-11-09-wii-launcher-design.md` (§3 UI, §4 Architektur, §9 Meilenstein M1)

## Global Constraints

- C++20, `-fno-exceptions -fno-rtti`, Warnungen als Fehler (`nl_apply_flags`); Fehler laufen über `nl::Result`.
- Keine Heap-Allokation pro Frame im Leerlauf des Hauptbildschirms; Puffer werden beim Start angelegt, Strings gecacht.
- Host-Code (`src/core`, plattformfreie Teile von `src/gfx` und `src/ui`) bindet keine libogc-Header ein.
- Logische Auflösung: 640×480 (4:3) bzw. 854×480 (16:9); 60 fps Ziel, Animationen 200 ms ease-out.
- Zeichensatz der UI: Latin-1 plus „…"; alles andere wird als `?` dargestellt.
- Dolphin läuft immer mit `-u <dev-user-dir>`; die private Dolphin-Konfiguration wird nie angefasst.
- Keine ROMs, ISOs oder WADs im Repo. Schriften nur unter OFL mit Lizenzdatei.
- UI-Texte in M1 deutsch, zentral in `src/ui/strings.hpp` (DE/EN-Umschaltung folgt in M6).
- Commits enden mit `Co-Authored-By: Claude <noreply@anthropic.com>`; kein Push ohne Freigabe.
- Log-Marker sind stabil: `NL_READY`, `NL_CMD <name>`, `NL_ALLOC_IDLE <n>`, `NL_SELFTEST_OK`, `NL_PANIC`, `NL_CRASH id=<n>`.

## Review Focus

1. **Ungültiges UTF-8 und Zeichen außerhalb Latin-1 in Titeln** – erwartet: `?` statt Absturz oder Lesen hinter dem Puffer (Test in Task 4).
2. **DrawList-Überlauf** (mehr Quads als Kapazität) – erwartet: überzählige Quads werden verworfen und gezählt, kein Schreiben hinter den Puffer (Test in Task 3).
3. **Zeiger gegen Steuerkreuz / keine Wiimote verbunden** – erwartet: ruhender Zeiger überschreibt den Steuerkreuz-Fokus nicht; ohne Zeiger bleibt alles per Tasten bedienbar (Tests in Task 6 und 8).
4. **Leere Bibliothek oder leerer Eintrag (Favoriten)** – erwartet: Leertext statt Division durch null oder Fokus auf nicht vorhandene Kachel (Test in Task 8).
5. **Auto-Thema über Mitternacht und `von == bis`** – erwartet: 20:00–07:00 ist nachts dunkel; `von == bis` bedeutet nie dunkel (Test in Task 2).

Zusätzlich ohne eigenen Punkt abgedeckt: sehr lange Titel (Ellipse/Umbruch, Task 4).

### Task 11: Absturzbildschirm, Selbsttest, CI

**Files:**
- Create: `src/core/crash_report.hpp/.cpp`, `src/platform/crash.hpp/.cpp`, `src/app/selftest.cpp`
- Modify: `src/app/main.cpp`, `CMakeLists.txt`, `.github/workflows/build.yml`, `README.md`
- Test: `tests/host/core/crash_report_test.cpp`

**Interfaces:**
- Consumes: `setPanicHandler`, `RawInput`, `InputMapper`, `SceneStack`, `MainScene::barIndex/focusIndex`, `wait_for_markers` / `--marker`.
- Produces:

```cpp
namespace nl {
struct CrashInfo { u32 exceptionId, pc, lr, msr, dar, dsisr; u32 gpr[32]; };
const char* exceptionName(u32 id);     // 3 "DSI", 4 "ISI", 6 "Alignment", 7 "Program", 8 "FPU"; sonst "Unbekannt"
using ReadWord = bool (*)(u32 addr, u32& out);             // false = Adresse nicht lesbar
int backtrace(u32 sp, ReadWord read, std::span<u32> out);  // folgt der Back-Chain: [sp] = nächster Frame, [sp+4] = LR
int formatCrashReport(const CrashInfo&, std::span<const u32> trace, char* out, size_t cap);
}
namespace nl::platform {
void installCrashHandler();            // setzt PPCExcptCurPanicFn und den nl-Panic-Handler
}
```

Wii-Seite (`platform/crash.cpp`, libogc 3: Header `tuxedo/ppc/exception.h`):

- `PPCExcptCurPanicFn = &onException;` mit Signatur `void(unsigned exid, PPCContext* ctx)`. `PPCContext` enthält `pc, msr, cr, lr, ctr, xer, gpr[32]`; `DAR` (SPR 19) und `DSISR` (SPR 18) per `mfspr` lesen.
- Der Handler loggt zuerst `NL_CRASH id=<exid> pc=<hex> lr=<hex>`, ruft `GX_AbortFrame`, richtet mit `CON_Init` eine Textkonsole auf dem aktuellen Framebuffer ein und gibt `formatCrashReport` aus (Ausnahmetyp, PC/LR/DAR/DSISR, GPR 0–31, Backtrace bis 16 Einträge), darunter „RESET oder START: zurück zum Homebrew Channel".
- `ReadWord` der Wii akzeptiert nur 4-Byte-ausgerichtete Adressen in MEM1 (`0x80000000–0x817FFFFF`) und MEM2 (`0x90000000–0x93FFFFFF`).
- Rückkehr: Schleife mit `PAD_ScanPads` / `SYS_ResetButtonDown`; bei RESET, GC-Start oder nach 30 s → `__reload()` (so wie der Standard-Handler von libogc; Interrupts sind im Handler aus, deshalb keine Wiimote).
- nl-Panic-Handler der Wii: loggt `NL_PANIC <expr> <file>:<line>`, dann `__builtin_trap()` → landet im selben Absturzbildschirm.

Selbsttest (zweites Ziel `nl_selftest`, gleiche Quellen plus `selftest.cpp`, Define `NL_SELFTEST`): ersetzt `WiiInput::poll()` durch ein Skript von `RawInput`-Frames und prüft den Zustand mit `NL_ASSERT`:

1. 30 Frames Leerlauf, dann `NL_READY`.
2. `Plus`, `Plus` → `barIndex() == 2` (NES, 8 Spiele), `focusIndex() == 0`. Dann `Right`, `Down` → `focusIndex() == 7`.
3. Zeiger auf die Mitte von Kachel 2 → `focusIndex() == 2`.
4. `HomeBtn` → `depth() == 2`; `B`, 15 Frames warten → `depth() == 1`.
5. `One+Two` → Debug-Overlay sichtbar.
6. Allokationszähler nullen, 120 Frames Leerlauf, `NL_ALLOC_IDLE <n>` loggen, `NL_ASSERT(n == 0)`. Zähler über `-Wl,--wrap=_malloc_r` (alle `malloc`/`new` der newlib laufen dort durch).
7. `NL_SELFTEST_OK` loggen, danach absichtlich `__builtin_trap()` → erwartet `NL_CRASH id=7`.
