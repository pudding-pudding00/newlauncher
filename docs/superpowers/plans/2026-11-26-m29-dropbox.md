# M29 Dropbox, Kopplungsseite, QR-Code, erweiterte Tastatur – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Dropbox als dritter Anbieter. Anmelden per PKCE ohne Umleitung: Die Wii zeigt einen QR-Code auf eine
Kopplungsseite im LAN. Dort führt ein Link zu Dropbox, und der angezeigte Code geht über ein Formular zurück. Als
Ausweichweg gibt es einen QR-Code direkt zu Dropbox und die Eingabe per Bildschirmtastatur.

**Architecture:** `DropboxProvider` nutzt die OAuth-Hülle aus M28 (`OAuthClient`). Der Code-Tausch mit Verifier liegt
in `core/oauth_device` (`exchangeAuthCode`). Im Netz-Thread erzeugt `CloudWorker` den Verifier und das 128-Bit-Token
der Kopplungsseite, veröffentlicht Autorisierungs-URL und Token und wartet auf einen Code. Den Code reicht der
Haupt-Thread mit `submitCode` weiter, er kommt vom Kopplungsserver oder von der Tastatur. Die Logik der
Kopplungsseite (Anfrage parsen, Token prüfen, HTML) und der QR-Encoder sind host-testbar in `core/`; `platform/pairing_server`
ist nur der Socket-Thread nach dem Muster von `RemoteServer`.

**Tech Stack:** C++20, devkitPPC/libogc, wii_tls v1.0.0, doctest, Python 3 (Fake-Server), Dolphin-Smokes.

**Spec:** `docs/superpowers/specs/2026-11-26-cloud-spielstaende-design.md` (Ziel 6 Dropbox, Ziel 7 Kopplung und
Eingabe, Ziel 8 Sicherheit)

## Global Constraints
- Alle Regeln aus M27/M28 gelten weiter (DE+EN, kein `<ogc/…>` in core, kein throw/RTTI, 0 Warnungen mit/ohne TLS,
  `wtls_*` nur im Netz-Thread, nur HTTPS, keine Tokens/Codes/IDs im Log).
- `config.ini [cloud] provider = none|drive|onedrive|dropbox`, `dropbox_app_key` (öffentlicher Client, **kein
  Secret**). Ohne App-Key ist Dropbox ausgegraut.
- Autorisierung: `https://www.dropbox.com/oauth2/authorize?client_id=<key>&response_type=code&code_challenge=<c>&code_challenge_method=S256&token_access_type=offline`
  (ohne `redirect_uri`, Dropbox zeigt den Code an). Token: `POST https://api.dropboxapi.com/oauth2/token`
  (`grant_type=authorization_code`, `code`, `client_id`, `code_verifier`; Refresh wie gehabt ohne Secret).
- PKCE (RFC 7636): Verifier = base64url(32 Bytes CSPRNG) = 43 Zeichen, Challenge = base64url(SHA-256(Verifier)).
- API `https://api.dropboxapi.com/2`, Inhalte `https://content.dropboxapi.com/2`; App-Ordner, Pfad `/<einheit>.zip`.
  Revision = `rev`. Upload `files/upload` mit `Dropbox-API-Arg`: `mode` `add` (ohne erwartete Rev) bzw.
  `{".tag":"update","update":"<rev>"}`, `autorename:false`, `strict_conflict:true`, `mute:true`.
- Dropbox meldet **alle** Endpunktfehler als 409. Die Abbildung geht über `error_summary`: `path/not_found` →
  NotFound, `path/conflict` → RevMismatch, sonst Failed. 401 → Unauthorized (über `OAuthClient`).
- Keine Meta in Dropbox. `hash` bleibt leer, Gerät und Zeit kommen aus dem Paket (`fillHash`, M28-Fix 3).
- Abmelden: `POST https://api.dropboxapi.com/2/auth/token/revoke` mit Bearer-Token, ohne Body.
- Kopplungsseite: Port **4301**, Pfad `/<token>` (32 Hex-Zeichen = 128 Bit aus `secureRandom`), **eine**
  angenommene Einsendung (danach 410), Ablauf **5 Minuten**, Seite DE+EN, Code im Klartext.
- QR: Byte-Modus, Versionen 1–10, Fehlerkorrektur M, Maske nach Strafpunkten (ISO 18004).
- Tastatur: Ebenen abc / ABC / 123 / #, bis **128** Zeichen, Maskierung (`•`) einstellbar.
- Marker: `NL_CLOUD_LINKED dropbox`, `NL_CLOUD_LINK code` (URL gezeigt), `NL_CLOUD_LINK badcode`,
  `NL_PAIR listen`, `NL_PAIR ok`, `NL_PAIR reject` (falsches Token / zweite Einsendung / zu groß), `NL_PAIR stop`.

## Review Focus
1. Zweite oder späte Einsendung auf der Kopplungsseite (nach Erfolg, nach 5 Minuten, falsches Token): nie ein zweiter
   Code an den Worker, Antwort 410/404, und Token sowie Code stehen nie im Log.
2. Von Dropbox abgelehnter Code (Tippfehler): Der Dialog bleibt offen, die Seite nimmt wieder eine Einsendung an und
   der Verifier bleibt gleich; erst B oder der Ablauf beendet die Anmeldung.
3. Dropbox-409 ohne `path/conflict` (z. B. `insufficient_space`, `too_many_write_operations`): nicht als
   RevMismatch werten, sonst entscheidet `preLaunchSync` in einer Schleife neu.
4. Kopplungsserver bei Netzwechsel/Abbruch: Der Thread endet beim Schließen des Dialogs sicher, auch mitten in einer
   halben Anfrage (Zeitlimit je Verbindung), und Port 4301 ist danach frei.
5. Lange Eingaben: Tastatur bei 128 Zeichen voll, und ein Code mit `-`/`_` lässt sich tippen.
